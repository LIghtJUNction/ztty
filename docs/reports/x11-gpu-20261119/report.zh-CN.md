# ztty X11 GPU 与画布恢复验证

日期：2026-11-19  
代码提交：[12a8e4686b8af7cd8bf780852c888e1483fa7c5d](https://github.com/LIghtJUNction/ztty/commit/12a8e4686b8af7cd8bf780852c888e1483fa7c5d)

## 结果

X11 窗口已接入共享 EGL/HarfBuzz 渲染器。完整字符簇、原生界面、图片、搜索栏和提示层在同一帧提交；运行时可以切换字体和渲染后端，原窗口、broker 与 PTY 保持同一身份。

本轮同时修复两处已复现的问题：缩放时提前显示尚未绘制的画布，以及 GPU 字体没有采用显示器实际 DPI。独立构建目录重新生成的二进制，与通过全部窗口验收的候选逐字节相同。具体来源和结果见 [验证摘要](validation.json) 与 [源码清单](source-sha256.json)。

## 渲染与资源边界

| 配置 | 行为 |
| --- | --- |
| renderer = auto | 默认值。尝试硬件 EGL；检测到软件 GL 驱动时使用 Xft。 |
| renderer = gpu | 显式使用 EGL/GLES 路径，允许软件 GL 驱动参与测试。 |
| renderer = software | 使用 Xft/XRender。 |

GPU 出错后放弃未完成帧，并安排一次完整软件重绘。切换后端不会替换 PTY。软件画布只有在终端内容与覆盖层全部画完后，才允许被 Expose 事件再次提交。

复杂文字由 HarfBuzz 整形，FreeType/Fontconfig 负责字形与字体回退；终端模型保存完整 emoji ZWJ、旗帜和组合字符，拖选复制保留原始 UTF-8。这里不声称实现完整 Unicode 双向段落排版。软件回退保留完整字符数据，但不承诺与 GPU 路径完全相同的复杂文字排版效果。

整形缓存按字体与完整文本匹配，最多保存 512 条、512 KiB 字符与 glyph 有效载荷；这不是整个进程的内存上限。字符簇到网格位置的映射避免为每个 glyph 重扫整段文本。GPU 纹理采样使用更高精度坐标，4096 列图像的逐列像素检查已通过。

SGR 5 与 SGR 6 分别采用 500 ms、250 ms 闪烁节奏。无相关文字、窗口失焦或同步输出期间，不保留多余的文字闪烁唤醒。斜体、完整字符复制、字体热重载和后端切换都纳入实际窗口验证。

## 缩放闪烁的证据

X11 的新 pixmap 不保证已经含有终端画面。旧代码收到 ConfigureNotify 后分配新画布，随后 Expose 会立即把它复制到窗口，完整重绘排在后面。

我们对冻结的旧版 ELF 跟踪真实 XCopyArea 源像素。在不初始化、不修改新画布内容的测试中，12 次缩放有 11 次先提交 alpha = 0 的透明背景，之后才恢复到配置的约 70%（alpha = 179）。这验证了缩放路径的透明度突变。

修复增加了画布有效状态：分配、缩放、隐藏与后端变化使旧状态失效；完整绘制结束后才重新标记为有效。相同 12 次缩放，新版提交 12 个完整帧，背景透明度保持正确，异常提交为 0。另一个使用测试色标记未绘制区域的回归也通过，避免依赖分配器碰巧返回什么像素。

| 私有 X11 场景 | 旧版原始像素 | 新版原始像素 |
| --- | --- | --- |
| 12 次缩放 | 11 次异常透明背景提交 | 0 次异常；12 个完整帧 |
| 6 次移出屏幕再移回 | 未发现异常 | 未发现异常 |
| 6 次外部隐藏再映射 | 未发现异常 | 未发现异常 |

当前用户桌面是 Hyprland。上面的结果确认了缩放路径，尚不能把实际桌面左右切换时的全部闪烁归因于它；仍需把该场景的窗口几何变化与此路径对应。测试没有测量物理显示器延迟。原始对照摘要见 [画布证据](canvas-comparison.json)。

## 字体尺寸的证据

同一个点字号，在独立 Fontconfig 默认值与 Xft 的显示器 DPI 下会得到不同的像素尺寸。例如私有 96 DPI X 服务器上，DejaVu Sans Mono 的 size=14 分别得到约 14.58 px 和 18.64 px。

旧 GPU 候选实际画出的 HMWH 高 11 像素，Xft 为 14 像素。新实现把 Xft 已解析的像素尺寸写入 GPU 字体请求；真实窗口测得两者都高 14 像素、顶部都在 y=5，字形边缘允许抗锯齿产生像素差异。回归先在旧候选上失败，再在新版上通过，未降低搜索栏或原子帧的断言。

## 验收

| 门禁 | 结果 |
| --- | --- |
| 实际 GPU 与字体库 | 6 项通过；硬件驱动为 NVIDIA GeForce RTX 4060 Laptop GPU |
| 文字闪烁状态 | 4 项通过 |
| 格式、严格工作区 Clippy、release、no_std 检查 | 全部通过 |
| 真实窗口文字、透明度、复制、重载 | 8 项通过 |
| 原生界面与图片交互 | 24 项通过 |
| 键盘、鼠标、焦点、快捷键 | 14 组，198 个向量，14 个缩放案例通过 |
| 重绘、同步输出与交互公平性 | 11 项通过 |
| 软件画布有效性 | 2 组检查通过，包含 24 次几何或可见性变化 |

窗口测试使用自有 Xvfb、真实 PTY、XTEST、私有剪贴板和 X11 像素读回。测试显式选择 GPU 路径，驱动为 llvmpipe；真实 NVIDIA EGL 库测试单独执行。两类证据分别记录，不把虚拟 X 服务器等同于物理显示器。

重绘检查保留单次完整提交、单行软件损伤、输入响应、150 ms 同步输出兜底和空闲无周期唤醒等要求。GPU 帧通过实际 eglSwapBuffers 跟踪；软件帧通过实际 XCopyArea 跟踪。启动阶段遗留的完整旧画面被单独识别，事务内的一次提交断言保持不变。

Linux 构建与打包已声明 Fontconfig、FreeType、HarfBuzz、EGL/GLES 和 pkg-config 依赖，并恢复原有的真实 libgcc_s 链接。正式 Linux 发布流程加入 GPU、完整文字与画布回归；本轮没有触发常规远程 CI。

这是可合入的开发分支。最终版本仍待历史回流、图形协议、OSC 52 与 native Wayland 整合，以及整合后性能基准和正式发布验收。这里没有用此前旧版本的吞吐数字代替最终候选基准。
