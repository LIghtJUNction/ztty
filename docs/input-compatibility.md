# Input protocol compatibility

The independent `zinput` codec remains `no_std`, uses `alloc`, forbids unsafe
code and adds no dependencies. Unit tests verify generated bytes. The separate
Linux X11 GUI gate below verifies delivery from X11 events through the frontend
to an actual raw PTY, including terminal mode negotiation.

## Changes and protocol evidence

| Case | Previous behavior | Implemented behavior | Primary reference |
|---|---|---|---|
| Ctrl+Shift character shortcuts in legacy mode | Shift collapsed into the Control mapping | CSI-u preserves the Shift bit; Space retains its NUL exception | [Kitty legacy text keys](https://sw.kovidgoyal.net/kitty/keyboard-protocol/#legacy-text-keys), [Ghostty keyboard encoder](https://github.com/ghostty-org/ghostty/blob/main/src/input/key_encode.zig) |
| Ctrl+tilde | Literal tilde | Control byte 30 | [Kitty legacy Control mapping](https://sw.kovidgoyal.net/kitty/keyboard-protocol/#legacy-ctrl-mapping-of-ascii-keys) |
| X10 tracking mode 9 | No report | Left, middle and right presses, with no modifier bits; no releases, motion or wheel events | [XTerm mouse tracking](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html#h2-Mouse-Tracking), [Ghostty mouse encoder](https://github.com/ghostty-org/ghostty/blob/main/src/input/mouse_encode.zig) |
| Wheel buttons 4–7 and extra buttons 8–11 | Only vertical `Scroll` events could be encoded | Distinct button codes, horizontal wheel presses, extra-button releases and dragging | [XTerm other buttons and extended coordinates](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html#h2-Other-buttons) |

Button numbers in `MouseEvent` are zero-based. Callers therefore pass `5` for
X11 button 6 and `7` for X11 button 8. Buttons beyond X11 number 11 are rejected
because their encoding overlaps modifier bits. Wheel releases and motion are
suppressed. Tracking mode and coordinate encoding remain separate decisions:
setting `sgr_mouse` does not turn tracking on.

The audit also checked existing Kitty alternate-key fields, base-layout fields,
modifier transition state, event subfields, F3 disambiguation and associated-text
release suppression. Those mechanisms already existed. New regression vectors
exercise them without asserting that all native input paths are verified.
[Kitty protocol](https://sw.kovidgoyal.net/kitty/keyboard-protocol/)

## Reproducible checks

Run from the repository root:

```sh
cargo test --locked -p zinput -j 1
cargo clippy --locked -p zinput --all-targets -j 1 -- -D warnings
cargo check --locked -p zinput --lib --target x86_64-unknown-none -j 1
```

The regression suite checks exact protocol vectors, all 32 Kitty flag
combinations for Enter/Tab/Backspace release rules, all eleven xterm button
numbers, invalid-button and coordinate overflow rejection, and append-only
buffer reuse. Unknown or filtered mouse events must append no partial sequence.
The bare-metal target check verifies that the library does not acquire a
standard-library dependency.

## Verified Linux X11 integration

The API keeps its existing public struct and enum shapes. Frontends can pass
extra button numbers through the existing `MouseEvent::Press`, `Release` and
`Motion` variants. `MouseEvent::Scroll` remains a vertical-wheel convenience.
The Linux frontend now routes all four wheel directions and buttons 8–11,
retains held extra-button state for dragging, and propagates terminal tracking
mode 9. Its release routing follows the owner of the original press when Shift
changes; local selection and configured actions cannot leak unmatched releases
to the PTY.

The real GUI regression in [tests/input_gui.py](../tests/input_gui.py) passed
all **27 vectors** against the immutable candidate with SHA-256
`b3d8fdb31d71ef9d1ed602b35673bf4648362fa354078e191e35a2cd75ac4631`.
The [JSON evidence](measurements/input-x11-2026-11-18.json) records exact expected
and received bytes, binary/test/source hashes, the source commit and changes,
pointer mapping, verified Xvfb socket ownership, and completed process cleanup.
The [actual window capture](assets/input-x11-2026-11-18.png) was visually checked:
text is readable on the black background, overlays are closed, and no stray
protocol bytes or drawing artifacts appear.

| Group | Vectors | Verified behavior |
|---|---:|---|
| Keyboard | 3 | Ctrl+I remains Tab; Ctrl+Shift+I produces distinct CSI-u; unshifted tilde plus Control produces byte 30 |
| Wheels | 4 | Buttons 4–7 produce distinct vertical/horizontal SGR press codes without release reports |
| Extra buttons | 8 | Buttons 8–11 retain identity on SGR press/release and mode-1002 drag motion |
| Shift and press ownership | 4 | Primary/extra releases retain their remote destination after Shift changes; a local Shift press produces no remote release |
| Focus | 1 | Mode-1004 focus-out/in replies acknowledge both real transitions; subsequent motion/release cannot reuse old held-button state |
| X10 and mode changes | 4 | Left-button presses ignore modifiers; wheel/extra/motion probes are filtered; SGR selection is independent; resetting mode 9 preserves subsequently selected mode 1000 |
| Configured actions | 3 | The custom search key and primary/extra mouse palette bindings consume their input and overlay text |

The private Xvfb pointer exposes buttons **1–10**. Tested buttons 1, 3 and 4–10
use XTEST, as do keyboard input and pointer movement. Button **11** uses
explicitly labelled `XSendEvent` press/release events with XTEST pointer motion
because this virtual device cannot generate button 11. This establishes X11
event routing for button 11; physical-device delivery remains a separate gate.
The Control+tilde case uses an unshifted tilde mapping on an unused keycode in
the private server, leaving the user's keyboard configuration untouched.

To reproduce, install Xvfb, Python Xlib and Pillow, build the Linux binary, then
run from the repository root:

```sh
python3 tests/input_gui.py \
  --binary target/release/ztty \
  --source-root "$PWD" \
  --output artifacts/input-gui.json \
  --screenshot artifacts/input-gui.png
```

The script uses an isolated runtime directory, broker socket and owned Xvfb.
It compares real PTY bytes, waits for focus reports rather than a fixed delay,
and fails if its owned processes remain after cleanup. The `--source-root` tree
must contain `tools/isolated_xvfb.py` and match the supplied binary.

## Remaining integration boundaries

This gate covers the listed Linux X11 paths. Native Wayland, macOS and Windows
event delivery, hardware buttons, IME/layout combinations, platform media keys,
UTF-8 mouse coordinates, URXVT encoding and SGR pixel coordinates require their
own acceptance tests. Complete Kitty/Ghostty equivalence is not established by
these vectors. Ghostty separates mode-aware encoding from the frontend event
source in its [input guide](https://lib.ghostty.org/vt/guide-input.html).
