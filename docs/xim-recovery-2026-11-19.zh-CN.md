# ztty 输入法重连修复与验收

本轮已修复 Linux X11/XWayland 的输入法生命周期问题：输入法服务晚启动或重新启动后，终端会重新建立 XIM 输入上下文，并恢复仍存活窗口的输入焦点。输入法暂时不可用期间，普通键盘输入继续工作。

生产源码提交：[6c44eb9bbece75594701e51cc9b439c31efb53c0](https://github.com/LIghtJUNction/ztty/commit/6c44eb9bbece75594701e51cc9b439c31efb53c0)。对应独立验证 ELF 的 SHA-256 为 `5ab07a927c84861332a37b12e9918677aab0968e7c3e450cec861bed3de214a8`。本记录描述该源码与隔离验收；安装版本和真实桌面窗口核验由整合交付记录给出。

## 现场原因

只读检查时，6 个现有 ztty 进程均运行已安装的 `0.4.1-5`，执行映像为 `8f35b08477877a798cc2d44ff4431731bdddd418c9c3c72097493c68cc3d2d0c`；它们的 `DISPLAY=:0`、`XMODIFIERS=@im=fcitx` 正确。这些进程启动于本地时间 2026-11-20 01:16:04–01:17:04，当前 fcitx5 则于 01:18:04 启动。此前 fcitx 的退出信号记录出现在 01:15:52、01:15:54。

当时 fcitx 能响应查询，独立新建的 `XOpenIM` 连接也成功，但已有终端在 fcitx 的 X11 组中没有有效 XIM 上下文。源码检查确认：旧版只在连接、窗口创建时调用一次 `XOpenIM`、`XCreateIC`，没有服务出现和销毁的回调。输入法晚于终端出现时，原来的空句柄一直保留；同一 broker 新开的窗口也会复用这条无输入法的连接。

私有桌面中的真实复现进一步区分了两条路径：

| 场景 | 已安装旧版的结果 | 修复版的结果 |
|---|---|---|
| 先开终端，再启动 fcitx | `nihao` 加空格仍直接写入 ASCII，同 broker 的第二窗口也失败 | 已有窗口自动接入，PTY 收到 UTF-8“你好” |
| 中文输入正常后停止 fcitx，再按普通键 | broker 在测试清理前因 `SIGSEGV` 退出，`waitpid` 信号值为 11 | 服务缺席期间继续接收 `abc`；服务恢复后继续输入中文 |
| 服务缺席时关闭一个窗口，再启动服务 | 旧版缺少恢复路径 | 仅重建仍存活窗口的上下文，焦点返回正确 |

这些观察及输入字节保存在[公开验证记录](measurements/xim-recovery-2026-11-19/validation.json)。测试只向自有私有显示中的窗口注入按键，实际用户终端和桌面输入法保持运行。

## 修复原理

每条 X11 连接仍共享一个输入法对象。连接订阅 Xlib 的“输入法可用”通知；服务出现后重新打开输入法，为仍存活的窗口创建输入上下文，并按保存的焦点状态恢复输入。窗口上下文使用稳定的 `Rc` 地址，连接保存弱引用，避免关闭窗口后重建失效对象，也不会形成引用循环。

输入法服务消失时，销毁回调只清空句柄。按照 [Xlib 的 Destroy Callback 合同](https://www.x.org/releases/X11R7.6/doc/libX11/specs/libX11/libX11.pdf)，回调之后输入法和上下文由 Xlib 销毁；应用此时再次释放，或继续使用原指针，都会出错。连接退出前注销通知，窗口销毁前释放仍有效的上下文。重连依靠事件通知，没有新增空闲轮询或 PTY 输出处理工作。

## 验收范围

同一修复版 ELF 完成以下检查，均通过：

- 37 项真实 XIM 生命周期检查：正常中文、晚启动、服务停止期间 ASCII、重复重启、同 broker 多窗口、焦点返回、服务缺席时关闭窗口。
- 上述 37 项涵盖两项确定性故障注入边界：首次打开失败后，注册可用回调时服务已存在；真实私有 fcitx 在 `XCreateIC` 返回前退出，销毁回调先于返回发生。故障注入只由测试进程加载的共享库执行，生产代码没有测试开关。
- 原有输入回归的 198 个向量及 14 个分组检查，包括小键盘、NumLock/Shift、Kitty 键盘协议、鼠标路由、快捷键和窗口切换。见[输入回归记录](measurements/xim-recovery-2026-11-19/input-gui.json)。
- release 编译、`cargo fmt --all -- --check`。所有隔离测试清理后，自有子进程残留为零。

可复用脚本为 [tests/xim_gui.py](../tests/xim_gui.py)。它使用私有 Xvfb、D-Bus、fcitx5 拼音配置、真实 XTEST 事件和原始 PTY 字节；需要 `fcitx5-chinese-addons`、`qdbus6`、C 编译器及已有 GUI 测试依赖。两个故障注入场景的 C 夹具在临时目录编译，清理只针对测试自身后代进程。

```sh
python3 tests/xim_gui.py --binary target/release/ztty --output artifacts/xim.json
```

本轮验证平台是 Linux X11/XWayland，未扩展或验证原生 Wayland、Windows、macOS 输入法路径。既有旧进程不会因包文件更新而加载新代码；安装整合版本后，新开独立窗口会进入当前构建的 broker。现有窗口及其任务可以保留，中文粘贴仍可作为过渡方式。
